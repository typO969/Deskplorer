DESKPLORER v1 - C#, winforms? // Win10+

-TRY TO LIMIT AS LITTLE MVVM AS POSSIBLE-

PRIMARY FUNCTION - Grouping of desktop icons into customizable "folders".
	-similar to how windows 3.1's program manager interface was in terms of grouping things, but directly on the desktop


WHAT IS SPECIAL ABOUT THESE GROUP ICON FOLDERS - these group icon folders open and close with a hover or a single click very quickly
	-the group icons exist in 1 of 2 states:
		-closed state: indesinguishable from other desktop shortcut icons in terms of interactions, except these can be locked into place if desired 
		-open state: upon opening, the icon animates to a small box/form exactly where the closed icon was and the box contains all the grouped icons in whatever order they were placed within it. inside these boxes the icons should be the same size as the desktop icon size, and they can be auto-organized like the desktop can do, or they can be manually placed/organized however the user wants them; they should also be scalable in size indepedent of the desktop icon sizes
	-i created some mockup images for reference
	-i dont think it will need WPF level of customizing, so winforms might work? but i could be wrong

	-they ALWAYS open directly above wherever its desktop icon is sitting. 
	-when the group is "closed" you cant see whats inside of it, you can only see the group icon. 
	-once the group is "opened" then all its contents are available for access and interaction.
	-folder groups are movable, but only when enabled from right click menu
	-closed icons should have some kind of tick mark or number display that shows the quantity of items held within.
		-see the mockup for some prototyped ideas on this

	-in terms of logistics, it should probably sit right on top the user desktop invisibly
	-the program should also allow for multiple desktops (virtual) and multiple screens (and resolutions) with no issues of inter-interactions between any of the mentioned

	-need to consider how and where these desktop icons are located in terms of saved data.
	-need to also consider how to deal with icon intersections or collisions where a desktop icon is placed underneath deskplorer item on accident or otherwise

SPECIAL/DIFFICULT TO IMPLEMENT FEATURES
It will need to have access to the desktop insomuchas being able to interact with whatever is currently on the desktop without being volatile or destructive. i doubt it is possible to completly convert a current desktop icon to a deskplorer item. but it should offer the ability to select any number of desktop icons and convert or copy and paste into the open folders.
